# 评委问答准备

这份文档用于路演后的 Q&A。回答要短、准、诚实，不要把 Demo 说成生产系统。

## 一句话怎么介绍？

DB Sentinel Agent 是一个只读数据库分析值班 Agent。业务同学用自然语言问数，系统生成查询计划和只读 SQL，先做安全校验，再返回表格、图表、业务解释和审计轨迹。

## 它是单独的 agent 吗？和 CC / Hermes 一个等级吗？

它是单独可运行的垂直 Agent 应用，但不是 CC / Hermes 级别的通用 agent 平台。

更准确地说：

```text
它是一个面向数据库分析值班场景的应用层 Agent workflow。
```

它有自己的工作流、工具调用、安全 guard 和审计记录，但不负责通用任务调度、跨项目协作、长期执行、消息总线或多 agent 编排。

## 和普通 NL2SQL 有什么区别？

普通 NL2SQL 主要解决“把自然语言变成 SQL”。DB Sentinel Agent 解决的是“可信问数工作流”：

- 查询前读 schema、拆指标和时间窗。
- 查询中展示 SQL，并通过 SQL guard。
- 查询后返回表格、图表、解释和下一步建议。
- 全过程有 session 和 audit record。

## 没有 LLM key 能跑吗？

能。当前 Demo 有确定性 fallback，覆盖 5 个样例问题，保证现场稳定。

需要诚实说明：

```text
当前版本验证的是 safe auditable workflow。LLM 是可替换生成层；fallback 用于保证 Hackathon 现场稳定演示。
```

## 现在 SQL 是 LLM 生成的吗？

当前 Demo 会封装 OpenAI-compatible client，但实际执行 SQL 使用确定性 fallback 模板。这样可以避免现场网络、key、模型波动影响演示。

后续可以把 fallback 替换为 LLM 生成 SQL，但必须继续经过同一个 `sql_guard` 和只读执行层。

## 为什么不用真实生产数据库？

这是有意设计。生产数据库涉及权限、脱敏、成本控制、审计合规和误操作风险。Hackathon 阶段用 SQLite 示例库，可以让评审安全体验核心闭环。

生产化路线是：

1. 接只读数据库账号。
2. 加 schema/table/column 权限。
3. 加指标语义层。
4. 加查询成本、超时和脱敏。
5. 审计落库。

## 安全边界是什么？

当前有三层：

- SQL AST guard：只允许单条 `SELECT` / `WITH`。
- 业务白名单：只允许访问示例业务表，拒绝 SQLite 内部表和 pragma。
- 只读执行：SQLite 使用 `mode=ro`，并开启 `PRAGMA query_only=ON`。

危险输入会返回“只读安全拦截”，不会执行 SQL。

## Reset 接口会不会破坏“只读”叙事？

默认不会。`POST /api/demo/reset` 默认返回 403，需要显式配置：

```ini
[database]
reset_enabled = true
```

这个接口只用于本地演示准备，提交版本保持关闭。

## 上传后怎么知道 API 和 URL 是什么？

看：

```text
config/app.conf
```

页面顶部也会展示当前 API 来源。后端还提供：

```text
GET /api/config
```

用于确认当前公开配置。

## 这个项目对业务有什么价值？

它把临时问数从“找人写 SQL”变成“在安全边界内自助分析”。价值不在省掉某一条 SQL，而在流程闭环：

- 业务更快得到初步结论。
- 数据同学少被重复问题打断。
- SQL、口径和结果能复核。
- 危险操作有硬拦截。

## 你们如何衡量效果？

当前 Demo 没有真实生产数据的量化指标，不应该声称已经节省固定比例时间。

可以用演示假设表达：

```text
传统临时问数可能需要 30 到 60 分钟排队沟通；Demo 中同类问题可以在几十秒内完成初步查询、解释和留痕。真实节省比例需要上线后按企业工作流测量。
```

## 还有哪些不足？

主要不足：

- 当前只覆盖内置示例问题。
- 审计记录仍在内存中。
- 没有企业级鉴权和权限模型。
- 没有真实数据库连接器和查询成本控制。
- LLM 生成 SQL 尚未完全接入执行链路。

这些不是隐藏问题，而是下一阶段生产化路线。
