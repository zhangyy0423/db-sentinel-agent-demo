## 🎯 Slide 1：项目封面

![DB Sentinel Agent 系统总览](assets/system-overview.svg)
_Figure 1: 封面建议直接使用系统总览图，评审不用等讲解就能理解项目形态。_

标题：

```text
DB Sentinel Agent
只读数据库分析值班 Agent 应用
```

副标题：

```text
业务同学直接问数，Agent 生成只读 SQL、执行查询、解释结果，并保留审计轨迹。
```

讲稿：

> 我们做的是一个面向业务数据分析值班的只读数据库 Agent。它不是只把自然语言翻译成 SQL，而是把问数、查数、解释和留痕变成一个安全可复核的工作流。

## 🎯 Slide 2：业务问数为什么慢

核心信息：

- 业务同学有大量临时数据问题。
- 数据分析师要反复理解口径、写 SQL、跑数、解释。
- SQL 和口径散落在聊天记录里，后续难复核。
- 如果直接让 Agent 接数据库，又会有写库、越权和口径乱编风险。

建议画面：

```text
业务问题 → 找数据分析师 → 确认口径 → 写 SQL → 跑数 → 解释 → 继续追问
```

讲稿：

> 这个流程不是技术上不能做，而是组织上很慢。业务等结果，数据同学被打断，最后 SQL 和解释还很难沉淀。

## 🎯 Slide 3：不是普通 NL2SQL

![Agent 六步闭环](assets/agent-workflow.svg)
_Figure 2: 用六步闭环解释项目差异化。_

核心信息：

| 普通 NL2SQL | DB Sentinel Agent |
| --- | --- |
| 重点是生成 SQL | 重点是完成数据分析值班闭环 |
| 通常只返回 SQL 或结果 | 返回计划、SQL、guard、表格、图表、解释 |
| 安全边界容易停留在提示词 | 用 AST guard 和只读连接做硬约束 |
| 过程难复核 | 每次会话有审计轨迹 |

讲稿：

> 真实工作里，生成 SQL 只是中间步骤。我们把 schema 理解、意图拆解、安全校验、执行、可视化和反思解释都显式展示出来。

## 🎯 Slide 4：Demo 场景

![GMV 查询结果截图](assets/screenshots/gmv-result.png)
_Figure 3: Demo 场景页建议直接放真实截图，让评审一眼看到 SQL、图表、表格和审计证据。_

核心信息：

当前 Demo 覆盖 5 类高频业务分析：

1. 渠道 GMV 排名
2. 渠道转化率下降定位
3. 618 活动 ROI 复盘
4. 商品类别退款率异常发现
5. 新用户首单转化城市差异

建议画面：

| 问题 | 业务价值 |
| --- | --- |
| 最近 7 天 GMV 最高的渠道是什么？ | 快速看经营结果 |
| 哪个渠道转化率下降最多？ | 找增长异常 |
| 618 ROI 最好的渠道是哪几个？ | 复盘投放效率 |
| 退款率异常升高的商品类别？ | 发现售后风险 |
| 新用户首单转化城市差异？ | 指导区域运营 |

讲稿：

> 这些不是玩具问题，而是运营、增长、活动、售后和新用户分析里每天都会出现的问题。

## 🎯 Slide 5：安全怎么保证

![只读安全防线](assets/safety-shield.svg)
_Figure 3: 安全页的核心是让评审相信它不会因为一句自然语言就写坏数据库。_

核心信息：

- 只允许单条 `SELECT` / `WITH`。
- 拒绝写操作、多语句、内部表、pragma 和危险函数。
- SQLite 执行层开启 `mode=ro` 和 `PRAGMA query_only=ON`。
- 危险请求会展示明确拦截原因。

讲稿：

> 我们没有把安全交给提示词，而是做了 SQL AST 解析和只读执行。现场可以输入 drop table，系统会拦截，不碰数据库。

## 🎯 Slide 6：现场演示路径

![危险请求拦截图](assets/screenshots/safety-block.png)
_Figure 4: 这页用于证明危险请求确实停在 guard 层。_

可备选放 `demo-storyboard.svg`，用于录屏开场说明。

演示顺序：

1. 问最近 7 天 GMV 最高渠道。
2. 展示 SQL、表格、图表和解释。
3. 问哪个渠道转化率下降最多。
4. 展示异常定位和下一步建议。
5. 输入危险请求。
6. 展示只读安全拦截。

讲稿：

> 我们用 3 分钟证明三件事：能查数、能解释、能拦截危险请求。

## 🎯 Slide 7：价值和扩展路线

![价值地图](assets/value-map.svg)
_Figure 5: 价值地图用于把 Demo 拉回组织价值和工程扩展。_

核心信息：

- 对业务团队：减少等待，自助完成常见分析。
- 对数据团队：减少重复临时 SQL，沉淀常见问题模板。
- 对治理安全：只读边界和审计轨迹可复核。
- 对工程系统：后续可接真实数据库、指标语义层、企业权限。

路线：

| 阶段 | 目标 |
| --- | --- |
| V1 | 接真实只读数据库连接器 |
| V2 | 接指标语义层，统一 GMV、转化率、ROI 口径 |
| V3 | 保存分析卡片，支持复核和分享 |
| V4 | 加权限、脱敏、限流、成本控制和审计落库 |

## 🎯 Slide 8：结论和评审检查项

结论：

```text
DB Sentinel Agent = 只读 + 安全 + 审计 的数据分析值班 Agent 应用
```

评审可现场检查：

- 无 LLM key 也能跑。
- 样例问题能返回 SQL、图表、表格和解释。
- 危险请求会被安全拦截。
- 每次会话能查看审计记录。
- `config/app.conf` 能说明上传后的 URL、API、端口和数据库路径。
- 技术上可扩展到真实只读连接器和企业权限体系。

边界表述：

```text
它不是 CC / Hermes 级别通用 agent 平台，而是一个垂直 Agent 应用，聚焦业务数据分析值班。
```

收束讲稿：

> 我们希望把数据分析师从重复临时问数里释放出来，同时让业务团队在安全边界内获得更快的数据反馈。这就是 Agent 重塑工作流的价值。
