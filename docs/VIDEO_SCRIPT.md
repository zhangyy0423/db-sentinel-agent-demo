# DB Sentinel Agent 演示视频脚本

_2 到 3 分钟演示视频脚本，用于参赛提交视频或现场备用录屏。_

---

## 📋 视频目标

视频要让评审在 3 分钟内看懂四件事：

1. 这个项目解决业务问数慢的问题。
2. 它不是普通 NL2SQL，而是可审计的 Agent 工作流。
3. 它能返回 SQL、表格、图表和业务解释。
4. 它能拦截危险写库请求。

```bash
npm run dev -- --host 127.0.0.1 --port 5173
```

打开浏览器：

```text
http://127.0.0.1:5173/
```

## 🎬 逐字旁白

### 开场

```text
这是 DB Sentinel Agent，一个面向业务数据分析值班的只读数据库 Agent。

业务团队每天都会问临时数据问题，比如最近 7 天哪个渠道 GMV 最高，哪个渠道转化率下降最多。传统做法是找数据分析师确认口径、写 SQL、跑数、解释，过程慢，而且很难复核。
```

### 工作台介绍

```text
这个 Demo 的首页就是工作台。左侧是数据库 schema、字段说明和样例问题；中间是 Agent 对话和它的分析过程；右侧是结果表格、图表和审计轨迹。
```

### GMV 演示

```text
我们先点击“最近 7 天 GMV 最高的渠道是什么？”

Agent 会先读取 schema，再拆解指标和时间范围，然后生成 SQL。SQL 通过 guard 校验后，才会用只读连接执行。结果会同时返回表格、图表和业务解释。
```

### 异常分析演示

```text
再看一个更像数据分析值班的问题：“哪个渠道转化率下降最多，可能原因是什么？”

这里 Agent 不只是查一个数，而是对比最近 7 天和前 7 天的访问量、订单量和转化率，定位下降最大的渠道，并给出可能原因和下一步拆解方向。
```

### 安全拦截演示

```text
最后看安全边界。我们输入“帮我 drop table orders”。

系统会生成危险 SQL，但 sql_guard 会识别它不是只读查询，所以直接拦截。右侧显示只读安全拦截，不执行数据库操作。
```

### 结尾

```text
DB Sentinel Agent 的重点不是自然语言转 SQL，而是把问数、查数、解释和留痕做成一个可信的数据分析值班工作流。

它让业务同学更快获得数据反馈，也让数据团队保留 SQL、口径、安全校验和执行结果，方便复核和治理。
```
